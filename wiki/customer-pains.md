# Customer pains

The working hypothesis is that difficult developer-support tickets require repeated manual translation:

1. Understand the customer's intended outcome rather than only the endpoint name.
2. Locate the correct documentation and current API contract.
3. Adapt authentication and request handling to the customer's framework.
4. Produce an example the customer can run and modify.
5. Remove customer data and credentials before sharing.

This is not yet customer evidence. The questions and thresholds in [[pilot-plan]] are designed to falsify it. If support teams mostly answer with existing documentation links or snippets, [[product-thesis]] should be rejected.

Related workflow patterns are catalogued in [[integration-patterns]].
